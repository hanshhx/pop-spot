# 개발 안내

POP-SPOT은 웹, 모바일 앱, 백엔드를 하나의 저장소에서 관리한다.

| 경로               | 역할                                               |
| ------------------ | -------------------------------------------------- |
| `popspot-frontend` | Next.js 웹 화면과 백엔드 요청 프록시               |
| `popspot-app`      | React Native·Expo 모바일 앱                        |
| `popspot-backend`  | Spring Boot API, 인증, 수집·검색·번역, 데이터 저장 |

## 작업 기준

- 변경 전 현재 브랜치와 작업 중인 파일을 확인한다. 다른 작업의 변경을 함께 커밋하지 않는다.
- 버전은 각 프로젝트의 의존성 파일과 잠금 파일을 기준으로 확인한다. Next.js는 설치된 패키지의 `node_modules/next/dist/docs/`도 참고한다.
- 모바일 앱의 Expo 버전은 `popspot-app/package.json`에서 확인한다. 다른 SDK 버전의 안내를 그대로 적용하지 않는다.
- 웹과 앱에서 공유하는 날짜·좌표·팝업 표시 규칙을 바꾸면 양쪽 구현과 테스트를 함께 확인한다.
- 주석은 설계 이유, 제약, 예외 처리를 설명한다. 변경 과정과 일회성 작업 보고는 커밋 설명이나 로컬 기록에 남긴다.
- 문서는 평서체로 쓴다. 측정값에는 측정 시점과 조건을 적고, 구현 완료와 운영 검증을 구분한다.
- 커밋에는 실제 변경 내용과 이유를 적는다. 도구의 자동 서명은 추가하지 않고, 실제 공동 작업자의 기여·라이선스·출처는 보존한다.
- 개인 도구 설정, 대화 기록, 임시 계획서, API 응답 덤프는 공개 저장소에 올리지 않는다. 이미 추적 중인 파일은 무시 규칙만 추가해도 추적이 해제되지 않는다.
- 인증 정보는 환경변수로 주입한다. 환경변수 예시는 값을 비운 `.env.example`로 관리한다.

## 검사

각 프로젝트 디렉터리에서 실행한다.

| 프로젝트 | 검사 명령                                                                                |
| -------- | ---------------------------------------------------------------------------------------- |
| 웹       | `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test`, `npm run build` |
| 앱       | `npx tsc --noEmit` (현재 `main`에는 별도 테스트 스크립트가 없음)                         |
| 백엔드   | `./gradlew spotlessCheck test bootJar`                                                   |

백엔드 빌드에는 Java 21이 필요하다. Windows에서는 `gradlew.bat`를 사용할 수 있다.
문서만 바꾼 경우 링크, 코드 예시, 서식과 변경 차이를 확인한다. 실행하지 않은 검사를 통과했다고 기록하지 않는다.

## 배포와 운영 문서

`.github/workflows/quality.yml`은 웹·백엔드 검사와 백엔드 JAR 보관을 담당한다.
백엔드 의존성 제출은 `.github/workflows/dependency-graph.yml`에 있으며 GitHub 의존성 그래프와 Dependabot 경보를 사용한다.
저장소에는 여러 배포 환경의 설정과 과거 이전 계획이 남아 있으므로, 실제 운영 대상은 배포 전에 별도로 확인한다.

릴리스는 기존 버전과 공개 상태를 유지하며, 요약 3개, 문제·원인·해결·결과 사례, 접힌 상세 내용을 사용한다.
