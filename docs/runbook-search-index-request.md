# 색인 요청 절차

검색엔진에 "이 페이지 좀 봐 달라" 고 손으로 넣는 작업. 구글 서치콘솔과 네이버 서치어드바이저
양쪽에서 같은 목록을 쓴다.

## 언제 하나

색인 재고가 늘었을 때. 2026-08-11 에 약관 §14-4 가 시행되면서 팝업 상세 396건이 `noindex` 에서
풀렸는데, 사이트맵에 올라간 것만으로는 검색엔진이 바로 오지 않는다.

**사이트맵이 대부분을 한다.** 손으로 넣는 것은 하루 10건 남짓이라 168건을 다 넣으면 17일이 걸린다.
마중물로 상위 10~20건만 쓰고 나머지는 사이트맵에 맡기는 것이 맞다.

## 목록 만들기

```bash
node scripts/index-request-list.mjs "<서치콘솔 인기검색어 CSV 경로>"
```

`docs/search-index-request-list.txt` 가 새로 쓰인다. CSV 없이 돌리면 남은 기간 순으로만 세운다.

CSV 는 서치콘솔 → 실적 → 내보내기 → 압축 파일 안의 "인기 검색어" 다.

### 목록이 거르는 것

| 거르는 것 | 이유 |
|---|---|
| 색인 자격 없음 | 마감일이 없거나 장소가 모호하면 검색한 사람 질문에 답할 수 없다. 프론트 `src/lib/indexableDetail.ts` 와 같은 규칙 |
| 7일 안에 끝남 | 색인이 붙기 전에 팝업이 끝난다. 요청 한도만 쓴다 |
| 같은 행사 | 한 행사가 <b>열한 가지 이름</b>으로 들어와 있던 적이 있다. 다 넣으면 검색엔진이 같은 내용의 페이지 열한 개로 본다 |

2026-08-12 실측: 자격 349건 − 곧끝남 105건 − 중복 76건 = **요청 168건**.

## 넣기

### 구글 서치콘솔

1. 상단 검색창에 URL 붙여넣기
2. **색인 생성 요청**

### 네이버 서치어드바이저

1. 요청 → **웹 페이지 수집**
2. URL 붙여넣기

RSS·사이트맵 제출은 한 번만 해두면 된다(이미 돼 있다). 네이버에서 즉효가 있는 것은 웹 페이지
수집뿐이다.

## 하기 전에 확인할 것

**502 가 잦으면 하지 마라.** 크롤러가 와서 실패하면 색인이 되기는커녕 "크롤해도 죽는 사이트" 로
평가된다. 2026-08-12 아침에 실패율이 53% 까지 올라간 적이 있다(`/var/log/popspot-probe.log`).

```bash
# 20회쯤 찔러 보고 실패가 거의 없을 때 넣는다
for i in $(seq 1 20); do curl -s -o /dev/null -w '%{http_code} ' https://popspot.co.kr/api/popups; done
```

## 결과 보기

며칠 뒤 서치콘솔 → 색인 생성 → 페이지.

```
색인 생성됨            늘어야 정상
'NOINDEX' 태그 제외    줄어야 정상
```

두 숫자가 반대로 움직이면 성공이다. 안 움직이면 크롤이 막히는 것이니 502 를 의심한다.

네이버는 리포트 → 사이트 진단의 **색인** 숫자를 본다. 구글보다 훨씬 느리다 — 2026-08-12 기준
구글 297건 / 네이버 43건이었고, 네이버는 7월 말에야 이 사이트를 훑기 시작했다.
