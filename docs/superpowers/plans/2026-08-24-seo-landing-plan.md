# SEO 랜딩 개편 — 실행 계획

2026-08-24. 원안: `팝스팟 SEO 랜딩 개편.dc.html`. 사용자 수정: 알림 이메일 → 의견 보내기,
도보 시간은 작전지도 것 재사용.

## 원안이 옳게 짚은 것

`/popups/[slug]` 가 **"지도 한눈에" 를 세 번 말하면서 지도가 없다.** 근거로 든 네 수치는 전부
`landingCopy.ts` 주석에 실제로 있고 대조해 확인했다 — 91% 이탈(322명 중 293명), 재방문 0.76%
(주 920명 중 7명), 목록 길이 상관 −0.15, 10위권 클릭 0 질의 295개.

축도 맞다: `결정 → 실행 → 재방문`.

## 다섯 항목의 실제 난이도

정찰 결과, 원안이 한 묶음으로 제시한 다섯이 **세 층으로 갈린다.**

|     | 항목                 | 판정                                              |
| --- | -------------------- | ------------------------------------------------- |
| 2   | 걸어서 묶기          | **지금 한다** — 비용 0, 새 호출 0                 |
| 3   | 의견 보내기          | **지금 한다** — 이미 링크로 있다. 폼으로 올리기만 |
| 4   | 곧 열리는 팝업       | **지금 한다** — 단, 기존 버그를 먼저 고쳐야       |
| 1   | 실제 지도            | **결정 필요** — 대역폭이 유일한 실제 비용 위험    |
| 5   | 사진 / 요일 / 입장료 | **못 한다** — 요일·입장료는 데이터가 없다         |

### 왜 도보 묶기가 공짜인가

작전지도의 도보 시간은 **라우팅 API에서 온 적이 없다.** `calculateRouteInfo`
(`app/planning/page.tsx:190-204`) 가 화면에 보이는 모든 도보 시간·거리의 유일한 출처이고,
내용은 하버사인 거리 × 1.3 ÷ 분속 67m 인 순수 산수다.

OSRM(`router.project-osrm.org`)은 **지도에 선을 그리려고만** 부르고, 응답의 `duration`·`distance`
는 버린다(`:176-179`). 실패해도 표시되는 숫자는 하나도 안 바뀐다.

그래서 랜딩에서 도보로 묶는 데 **네트워크 호출이 0번**이다. 처리방침도 손댈 게 없다 — 개인정보
처리 자체가 발생하지 않는다.

**OSRM 을 랜딩에서 부르면 안 된다.** 공개 데모 서버라 SLA 가 없고 대량 사용을 금지한다. 게다가
처리방침의 이전 목적이 "**작전지도** 도보 경로 계산", 이전 항목이 "**사용자가 선택한** 좌표",
시점이 "요청한 시점" 이다 — 로그인 없는 랜딩에서 페이지 열자마자 부르면 세 조건 모두 어긋난다.

### 왜 의견 보내기가 이미 반쯤 되어 있는가

`page.tsx:1071` 이 이미 `<FeedbackNote>` 를 그린다 — "이 목록에 빠졌거나 틀린 팝업이 있나요?"
카드에 `/feedback` 링크. 그 컴포넌트 주석이 이번 제안과 같은 말을 한다: _"새 폼을 만들지 않고
기존 /feedback 페이지로 보낸다 — 게스트도 그대로 작성 가능."_

`POST /api/feedback` 은 공개이고 `FeedbackForm` 은 `userId: string | null` 로 게스트를 이미 받는다.
**백엔드 변경이 필요 없다.**

그래서 할 일은 "의견 보내기를 넣는다" 가 아니라 **"링크를 그 자리 폼으로 올린다"** 로 좁아진다.

### 왜 사진·요일·입장료를 못 하는가

- **요일 · 입장료** — `PopupStore` 에 컬럼이 없고, DTO 에도 `types/popup.ts` 에도 없다.
  크롤러 추출 + DB 마이그레이션 + **jar 수동 배포**가 필요하다. 프론트 배포에 못 얹는다.
- **사진** — `/api/map/markers` 가 이미지 필드를 안 준다. 그것도 의도된 것으로, DTO 를 전부
  스칼라로 두려고 그랬다는 주석이 붙어 있다. 역시 백엔드 배포가 필요하다.
  그리고 정직성 문제가 하나 더 있다: 이미지 1,174장 중 789장이 Pexels, 385장이 Unsplash 로
  **사실상 전부 스톡 사진**이다. 랜딩 카드마다 스톡 사진을 붙이면 "그 팝업의 사진" 처럼 읽힌다.

## 계획

### 1단계 — `ddayOf` 를 먼저 고친다 (곧 열리는 팝업의 전제)

`page.tsx:292` 의 `ddayOf` 가 **종료일만 본다.** 그래서 5일 뒤에 열고 30일 뒤에 닫는 팝업이
지금 목록에서 라임색 "진행 중" 배지를 달고 있다.

이걸 안 고치고 "곧 열리는 팝업" 섹션을 더하면, 같은 팝업이 두 곳에 서로 다른 상태로 나온다.
**섹션보다 이 버그가 먼저다.**

### 2단계 — 곧 열리는 팝업

`startDate` 가 오늘 이후인 것을 모아 마감일이 아니라 **여는 날 순**으로. 데이터는 다 있다.

### 3단계 — 걸어서 묶기

`calculateRouteInfo` 를 `app/planning/page.tsx` 밖으로 꺼낸다. 지금은 `'use client'` 파일 안의
모듈 상수라 다른 데서 못 쓴다. 순수 함수라 그대로 옮겨진다.

좌표가 있는 팝업끼리 도보 N분 이내로 묶어 "이 셋은 걸어서 12분" 식으로 보여준다.

**좌표 공백을 정직하게 다룬다.** 성수는 98곳 중 65곳(66%)만 좌표가 있고, `other` 는 284곳 중
170곳(60%)이다. 묶이지 않은 것을 숨기면 목록이 조용히 3분의 1 짧아진다 — 묶인 것을 위에,
나머지는 그대로 아래에 둔다.

### 4단계 — 의견 보내기를 폼으로

`FeedbackNote` 의 링크를 `<FeedbackForm userId={null} />` 클라이언트 섬으로 바꾼다.
떠나지 않고 그 자리에서 쓴다.

**같이 고칠 것**: `page.tsx:1193` 이 `href="/feedback"` 를 하드코딩해서 `/en/popups/*` ·
`/ja/popups/*` 방문자가 한국어 페이지로 떨어진다. 폼으로 바꾸면 링크 자체가 없어져 이 버그도
같이 사라진다.

**주의**: 제보(`/api/popups/report`)와 의견(`/api/feedback`)은 다른 기능이다. 제보는 승인 대기열로
가서 데이터가 되고, 의견은 안 된다. "이 목록에 빠진 팝업" 이 목적이라면 제보가 맞는 경로다 —
헤더 주석(`Header.tsx:180-193`)에 2026-08-09 에 같은 이유로 제보를 게스트에게 연 경위가 적혀 있다.
**이번에는 의견으로 간다**(사용자 지시). 다만 목적이 "빠진 팝업 제보" 로 좁혀지면 경로를 바꿔야 한다.

### 보류 — 실제 지도

원안의 헤드라인이지만 **유일하게 실제 비용이 걸린다.**

`public/seoul.pmtiles` 가 **58.9MB** 이고 Vercel CDN 이 HTTP range 로 직접 서빙한다. 지금은 지도를
쓰는 사람만 타일을 받지만, 랜딩 840개에 지도를 얹으면 **검색으로 들어온 모든 방문자**가 스크롤할
때마다 받는다. 0원 제약에서 이게 가장 큰 노출이다.

부수 문제 둘:

- **좌표 34% 공백** — 성수 기준 3분의 1이 지도에 안 찍힌다. "지도 한눈에" 라고 해놓고 3분의 1이
  없는 지도를 보여주는 셈이다.
- **계절이 어긋난다** — `MapGL` 은 `useSeason()` 으로 루트 `<html data-season>` 을 보는데, 랜딩은
  `<main>` 에 자기 계절을 건다. 한 화면에 계절이 둘이 된다.

패키지는 이미 있다(maplibre-gl, pmtiles). **막는 것은 코드가 아니라 대역폭이다.**

## 범위 밖 — 그러나 따로 봐야 할 것

**`/api/tmap/route` 가 위험하다.** 유료 TMAP 키를 쓰면서 인증이 없고(`SecurityConfig` 의
`/api/**` permitAll), 방어는 IP 당 20회/분 하나뿐이다. 그리고 **호출부가 하나도 없다** —
프론트·앱 어디에도 없고 git 이력에도 없다. 쓰지도 않는 유료 엔드포인트가 열려 있다.

이번 작업과 무관하지만 **닫거나 인증을 거는 편이 낫다.** 별건으로 다룬다.

## 사실 정정

원안과 어제 내 분석 양쪽의 오류다.

- **"SSG 라 빌드 때 계산하면 된다" 는 틀렸다.** `generateStaticParams` 가 840 URL 을 내놓지만
  마지막 빌드가 실제로 프리렌더한 것은 4개뿐이고 `/popups/*` 는 없다. 이 페이지는 ISR
  (`revalidate = 3600`)로 돈다. "빌드 때" 라는 말이 성립하지 않는다.
- **어제 내가 "도보 시간은 TMAP/OSRM 이 필요해 0원과 부딪힌다" 고 뺐던 것은 잘못이다.**
  도보 시간은 산수였고, 이미 만들어져 있었다.

## 정할 것

**지도를 넣을 것인가.** 원안의 출발점이 "지도가 없다" 인데, 그것만 유일하게 비용이 걸린다.
넣는다면 대역폭을 어떻게 막을지(줌 제한 · 지역 타일 분리 · 정적 이미지 대체)를 먼저 정해야 한다.
