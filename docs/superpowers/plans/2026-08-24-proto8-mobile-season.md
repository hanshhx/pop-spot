## 2. 문서가 틀린 곳 — 여기부터 읽는다

전부 지금 리포와 대조해 확인했다. 이관 전에 알아야 할 것들이다.

### 2.1 "폰에는 계절이 `--s-bg` 하나뿐" — 홈에서는 **틀렸다**

문서의 출발점이자 가장 큰 오류다. 홈에는 이미 모바일 전용 배경이 있다.

`app/globals.css:707-782` — `@media (max-width: 767px)` 안의 `.home-flat-bg` 가 라임 방사형
그라디언트 · 격자선 · 지평선 · SVG 노이즈를 그린다. 그리고 그 라임은 **계절별로 완전히 교체된다**:

|      | `--color-lime-400` |
| ---- | ------------------ |
| 봄   | `#ff95bc` 분홍     |
| 여름 | `#29d0ec` 청록     |
| 가을 | `#ffa431` 주황     |
| 겨울 | `#82c4f0` 파랑     |

라이브(375px)에서 실측: `--s-bg #f5fafb` · `--color-lime-400 #29d0ec` · `.home-flat-bg` 높이 812px,
청록 그라디언트가 실제로 그려진다. **구분이 안 되는 상태가 아니다.**

다만 그건 홈에만 있다. 라이브 HTML을 받아 확인한 결과:

| 경로             | 배경 요소                 | 모바일에서 계절을 전하는 것 |
| ---------------- | ------------------------- | --------------------------- |
| `/`              | `.home-flat-bg`           | 계절 라임 그라디언트 전면   |
| `/login`         | `<video>` (모바일 제외됨) | `--s-bg` 하나뿐             |
| `/signup`        | 없음                      | `--s-bg` 하나뿐             |
| `/popups/{slug}` | 없음                      | `--s-bg` 하나뿐             |

**그래서 제안이 실제로 겨냥해야 하는 곳은 홈이 아니라 나머지다.** 홈에 그대로 적용하면 이미
있는 계절 배경 위에 또 한 겹을 얹게 된다.

### 2.2 영상이 모바일에 안 깔리는 이유가 문서와 다르다

문서: `<source>` 에 `media="(min-width: 768px)"` 가 걸려 있다.
실제: `LoopingBgVideo.tsx:442,459` 의 `<source>` 는 **맨몸이다.** 차단은 자바스크립트가 한다 —
`useShouldRender()` (`:44-46`) 가 `(min-width: 768px)` **와** `(prefers-reduced-motion: no-preference)`
둘을 함께 보고, 어긋나면 `:422` 에서 `<video>` 자체를 마운트하지 않는다.

차이가 중요한 이유 두 가지.

- **관문이 둘이다.** 좁은 화면뿐 아니라 **움직임 축소를 켠 사람도** 영상을 못 받는다. 데스크탑
  사용자 중에도 있다. 문서는 이 층을 모른다.
- 문서가 인용한 문자열은 **다른 파일에 있다** — `app/login/page.tsx:200`. 거기서도
  `and (prefers-reduced-motion: no-preference)` 가 더 붙어 있다.

`git log -S` 로 확인: 그 속성은 `LoopingBgVideo.tsx` 에 **한 번도 있던 적이 없다.**

### 2.3 "영상 위 베일 62%" — 숫자는 맞고 화면이 다르다

62% 는 **로그인 페이지**의 것이다(`app/login/page.tsx:207`,
`bg-[color-mix(in_srgb,var(--color-background)_62%,transparent)]`).

홈은 다르다. `app/globals.css:835-853` 의 `.home-video-scrim` 은 **5단 세로 그라디언트**이고,
`rgba(251,249,243,…)` / `rgba(8,9,12,…)` 로 **하드코딩**돼 있다 — 계절 토큰을 안 쓴다. 로그인 쪽은
`var(--color-background)` 를 쓰는데 홈은 안 쓴다.

### 2.4 자잘하지만 값을 다루는 곳들

- **`--s-bg` 97%** — 셋은 97.3~97.5% 지만 **가을은 95.9%** 다. 1.5%p 차이. "사계절 모두 97%" 는
  가을에서 틀린다.
- **로고** — `.sp{fill:var(--s-hi)}` 로 SPOT 네 글자만 계절색인 것은 맞다. 그러나 바스켓이
  전부 `currentColor` 라는 것은 틀렸다. 테두리와 점은 `.st1{fill:#b8d565}` 로 **사계절 고정
  하드코딩**이다(`Logo.tsx:30`, 의도된 것이라는 주석이 `:18-22` 에 있다).
- **`--s-muted` 가을 `#7d6444`** — 맞다. 제안값 `#6f5738` 은 리포에 없다(아직 제안이다).
- **`PopupCalendar` 날짜 칸이 `bg-cream-300`** — 맞다(`:184-192`). 다만 **문제가 더 넓다**:
  지역 칩(`:276`)과 목록 행(`:360`)도 같은 중립색이다. 그리고 칸 수는 31 고정이 아니다.
- **`DOCK_ITEMS` · `--color-hot-400 #ff3d7f` · 헤더 우측 구성 · 계절 인프라 5종 · 랜딩 실측 수치
  4건** — 전부 사실 확인.

### 2.5 문서가 스스로와 어긋나는 곳

디자인 문서 내부의 모순이다. 이관자가 값을 그대로 옮기면 그대로 들어온다.

- **가을 `--s-bg` 제안 `#f8e9d4` 는 90.2%** 로, 문서가 스스로 정한 "92~93%" 범위 **밖**이다.
  나머지 셋은 92.7 / 92.4 / 93.3 으로 범위 안이다.
- **가을 4.5:1 대비 주장은 띠(`#f2d6a8`) 기준일 때만 성립한다.** 새 바탕 `#f8e9d4` 에 대해서는
  **기존 `#7d6444` 도 이미 통과한다.** 즉 `--s-muted` 를 바꿀 근거가 문서 안에서 무너진다.
- 봄·여름·겨울의 대비 수치는 **아예 없다.** 가을 하나만 적혀 있다.
- 문양·번짐 레이어 알파를 "7~18%" 라고 적어 놓고 코드에서는 11 / 18 / 26 / 32% 를 쓴다.
  "만채도는 화면의 10% 이내" 규칙을 지켰다는 주장이 이 잘못된 범위 위에 서 있다.
- `--s-band` 는 **새 토큰**이다. 정본 토큰 문서(`팝스팟 계절 색감.dc.html`)에는 없고 이번 문서와
  SEO 랜딩 문서에만 나온다. 리포에도 없다(`s-band` 전체 검색 0건).

### 2.6 4화면 핸드오프는 상당 부분 낡았다

`팝스팟 확정안 개발 핸드오프.dc.html` 은 그대로 붙여넣으면 깨진다.

- **4c 도크** — `DOCK_ITEMS.slice(0,4)` 를 기본 4칸으로 가정한다. 지금은 명시 키 목록
  `['MAP','COURSE','SCHEDULE','MY']` 다. **이 문서가 쓰인 뒤 동행이 일정으로 바뀌었다.**
- `--dock-h: 68px` 은 `sm` 미만에서만 맞다. 버튼이 `sm:h-16` 이라 640px 이상에서는 76px 다.
- `--safe-b` 를 `max(0.75rem, …)` 로 정의하는데 실제 도크는 `max(0.5rem, …)` 로 떠 있다.
- **4d 랜딩 수정은 적용 불가** — 대상 요소가 리포에 존재하지 않는다.
- 배경이 라임 hex 세 개를 하드코딩하는데, `--color-lime-300` 은 이제 계절별로 교체된다.
- 다섯째 칸은 문서가 **롱프레스**를, 리포는 **팝오버**를 쓴다. `aria-current` 를 확인하라고 하는데
  리포는 `aria-pressed` 다.

## 4. 계획

문서를 그대로 옮기지 않는다. 검증에서 살아남은 것만, 겨냥할 곳을 바로잡아서 옮긴다.

### 1단계 — 홈이 아닌 화면의 계절 바탕 (핵심)

대상은 **로그인 · 회원가입 · SEO 랜딩**. 홈은 제외한다(2.1).

`globals.css` 의 계절 블록 여덟 개 안에 `@media (max-width: 767px)` 를 열고 라이트 네 계절의
`--s-bg` 를 내린다. 값은 문서 그대로:

|      | 현재      | 제안                       |
| ---- | --------- | -------------------------- |
| 봄   | `#fdf7f4` | `#f8e7e1`                  |
| 여름 | `#f5fafb` | `#e3f0f4`                  |
| 가을 | `#fdf6ec` | `#f8e9d4` ← 90.2%, 범위 밖 |
| 겨울 | `#f6f9fb` | `#e8eef4`                  |

**가을만 다시 정한다.** 92~93% 로 맞추려면 `#f8e9d4` 보다 밝아야 한다. 나머지 셋과 같은
기준으로 다시 뽑는다.

`--s-muted` 는 **바꾸지 않는다.** 문서가 든 근거(가을 4.5:1)가 새 바탕에서는 기존 값으로도
충족된다(2.5). 바꾸려면 네 계절 대비를 새로 재고 그 숫자를 근거로 삼는다.

`--s-band` 는 이 단계에서 넣지 않는다 — 3단계로 미룬다.

**검증**: 네 계절 × 라이트/다크 × 세 화면을 375px 에서 열어 본문 대비가 AA(4.5:1)를 넘는지
숫자로 확인한다. `app/season-preview` 가 이미 QA 화면이므로 거기에 세 화면을 얹는다.

### 2단계 — 일정 화면의 계절 실종

`PopupCalendar` 는 아홉 화면 중 계절이 가장 안 보이는 화면이다. 날짜 칸 · 지역 칩 · 목록 행이
모두 중립 `bg-cream-300` 이다(2.4).

날짜 칸을 `--s-soft` 로 바꾼다. **선택·호버·오늘 표시는 문서에 없으므로 직접 정하고**, 정할 때
선택 상태(`bg-ink-900`)와의 대비를 함께 잰다.

지역 칩과 목록 행은 같은 문제지만 문서 범위 밖이다. 1·2단계를 보고 판단한다.

### 3단계 — 질감 (TURN 2)

계절별 4레이어 회화 질감(봄 꽃잎 · 여름 물빛 · 가을 잎 · 겨울 눈)과 `--s-band`.

**1·2단계를 배포해 보고 결정한다.** 이유 셋:

- 홈에는 이미 `.home-flat-bg` 라는 질감이 있다. 두 벌이 되면 어느 쪽이 정본인지 모호해진다.
- 알파 수치가 문서 안에서 어긋난다(2.5). 면적 규칙을 다시 재야 한다.
- `SeasonBg.dc.html` / `SeasonScene.dc.html` 은 그레인을 180px 래스터로, 모바일 문서는 140px
  인라인 데이터 URI 로 쓴다. **세 문서가 서로 다르다.** 어느 것이 정본인지 정해야 한다.

### 손대지 않는 것

- **4화면 핸드오프(4a~4d)** — 낡았다(2.6). 되살리려면 문서를 다시 받아야 한다.
- **SEO 랜딩 개편** — 별건이고 분량이 크다. 게다가 알림 이메일은 개인정보 처리방침의 수집 항목
  갱신이 필요하고, 도보 시간은 TMAP/OSRM 을 빌드 때 호출해야 한다. **0원 제약**과 부딪히는지
  먼저 따로 봐야 한다.
- **데스크탑** — 매니페스트가 "데스크탑 무변경" 이라고 못박았다.

## 5. 정할 것

1. **가을 `--s-bg`** — 문서값 `#f8e9d4` 는 문서 자신의 범위를 벗어난다. 다시 뽑을까, 아니면
   가을만 더 진하게 가는 것이 의도였을까.
2. **홈 제외가 맞나** — 홈에도 어두운 바탕을 적용하면 `.home-flat-bg` 와 겹친다. 겹치게 둘지,
   홈은 지금 그대로 둘지.
3. **`--s-muted`** — 근거가 무너졌는데도 함께 옮길지.
4. **그레인 정본** — 180px 래스터 · 140px 인라인 · 현재 `.home-flat-grain` 중 무엇을 쓸지.
