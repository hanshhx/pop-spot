# 발견 — 개별 개발계획 (마스터 플랜 §4.4 · 작업 4)

작성 2026-09-09. 근거는 같은 날 돌린 코드 조사(4영역 + 비평)와 **실제 분류 함수로 잰** 운영 재고다.

## 0. 이 계획이 기획을 두 군데 줄인다

§4.4 는 공개 가이드 3개와 취향 탐색을 함께 요구한다. 조사 결과 **가이드는 1개만 자격이 있고,
그 1개도 지금은 착수할 수 없다.** 근거는 §1.2 자신에 있다 —

> 공개 가이드 3개를 제작함. **조건이 확인된 재고가 부족하면 수량을 맞추려고 생성하지 않음.**

**3 은 채워야 할 할당량이 아니라 상한이다.** 그래서 1차는 **취향 탐색 하나**로 좁힌다.

| 기획의 가이드 | 판정 | 근거 |
|---|---|---|
| 함께 방문할 곳 | **불필요** | 랜딩의 `walkGroups` 가 이미 답한다 — 282 슬러그 × 3언어에 배포돼 있고 문구도 `landingCopy.walkHeading` 로 3언어가 있다. §4.4 공개 주소 원칙("기존 랜딩으로 답할 수 있으면 재사용")이 그대로 적용된다 |
| 목적별 비교 | **만들면 안 됨** | 2026-09-07 에 배포한 §4.3 비교와 질문이 같다(`compareSelection`+`compareRows`+`CompareModal`). §1.3 이 금지한 "같은 역할로 새로 만들기" 다. 게다가 축(전시·체험·굿즈)이 데이터에 없다 — `CATEGORIES` 는 7종이고 '굿즈' 는 character 의 keywords 원소, '전시' 는 art 의 keywords 원소다 |
| 확인된 방문 조건 | **자격은 있으나 지금은 불가** | 아래 |

### 남은 1개가 막힌 이유 — 비교가 이미 내린 판정과 같다

`compareRows.ts` 가 2026-09-07 에 결론을 냈다: 입장 조건과 비용은 **"값이 비어 있는 게 아니라
담을 그릇이 없다"** — 엔티티 컬럼 · V1~V33 마이그레이션 · 목록/상세 DTO · LLM 추출 프롬프트
넷 다 없다. **"확인된 방문 조건" 가이드는 비교가 만들 수 없다고 판정하고 포기한 바로 그 두 칸을
페이지 하나로 만들라는 요구다.**

유일하게 확인 가능한 `reservationUrl` 마저 막혀 있다. `PopupPublicListDto` 주석이 화이트리스트
근거와 함께 `officialUrl`/`reservationUrl` 을 **뺀 필드**로 명시한다. 목록으로는 못 읽고 유일한
경로가 `GET /api/popups/{id}` 인데 그것은 **쓰기다**(조회수 증가 + YouTube 호출). 카드 6장을
데이터로 그리면 볼 때마다 쓰기 6번이 난다.

그리고 §4.4 는 가이드를 자동 생성물이 아니라 **편집물**로 규정한다 — "대상 독자·선정 이유·
차이·주의사항·적용 기간·**확인일**·관련 링크". 확인일이 붙는다는 것은 사람이 확인한다는 뜻이고
곧 **재확인 책임**이 생긴다는 뜻인데, 누가 언제 재확인하는지는 플랜에 없다.

**그래서 이 가이드는 작업 3 이 확인 방법론과 대상 랜딩 3개를 내놓은 뒤에 편집물로 착수한다.**

## 1. 취향 탐색 — 새로 만들 것이 하나뿐이다

필요한 것이 이미 배포돼 있다. 조사에서 확인한 것:

| 기획 요구 | 이미 있는 것 |
|---|---|
| 지역·분야로 거르기 | `runPopAllQuery(popups, query, today)` — `region`·`category` 를 받는다 |
| **재고 없으면 조건 완화 안내, 임의 추천 금지** | `relaxSuggestions` — 조건을 하나씩 풀어 **실제로 세고**, 풀어도 0인 조건은 제안하지 않는다 |
| 지역 목록 | `REGIONS` 12개 (`regions.ts`, v2.21→v2.53). `labelEn`·`labelJa` 를 정의에 들고 있어 서버 컴포넌트 제약을 안 탄다 |
| 분야 목록 | `CATEGORIES` 7개 (`popupSlices.ts`) |
| 조건 고르는 UI 선례 | `PopAllFilterBar.tsx` |
| '관심 있어요' | `PopupCard` 의 `onWish`/`wished` — **타입에 자리가 뚫려 있고 호출부가 0개다** |
| 발견 자리 | 홈 하단 발견 존(`HomeClient.tsx:2238`, `PopAllPreview`) |
| 결과 페이지 | `/popups/<지역>-<분야>` **84장**이 `generateStaticParams` 로 이미 생성·색인 중 |

**새로 만드는 것은 '넘기기' 저장소 하나뿐이다.**

### 여기서 나온 것 셋

**① `lifestyle` 은 원천이 없다.** 전 지역 0건이다. DB 가 쓰는 category 값은
`FASHION·FOOD·CHARACTER·BEAUTY·CULTURE·ETC·TECH` 일곱인데, `lifestyle` 의 keywords 는
`['라이프','리빙','홈','lifestyle']` 이라 **어느 값도 매칭되지 않는다.** 고를 수는 있는데 항상
빈손인 선택지다(POP-ALL 모달은 오늘도 그렇다).

다만 **공개 페이지 쪽은 이미 스스로를 지킨다.** sitemap 은 `categoryCounts > 0` 으로 걸러
`lifestyle` 을 빼고, `/popups/lifestyle` 은 200 이지만 `noindex` 가 붙는다(운영 확인).
남는 것은 `landingLinks` 가 거르지 않아 생기는 내부 링크 하나뿐이다.

**그러므로 고칠 자리는 `CATEGORIES` 가 아니라 새로 만드는 UI 다.** 취향 탐색이 렌더 시점에
재고를 세어 0 인 선택지를 감추면 `lifestyle` 은 저절로 사라지고, 앞으로 생길 어떤 불균형도
같은 방법으로 처리된다.

**② `ETC` 103건도 이미 닿는다 — 처음에 "못 닿는다" 고 적었던 것은 틀렸다.**
`PopAllFilterBar.tsx:110` 이 `<option value="other">` 을 **손으로 넣어** 두었고, i18n 에
`popall.categoryOther`·`popall.regionOther` 가 3언어로 있다. `matches()` 는
`classifyCategory(p.category) !== query.category` 로 거르므로 `other` 를 고르면 ETC 가 정확히
잡힌다.

**여기서 구조를 하나 배웠다 — 두 층이 일부러 갈라져 있다.**

| | 무엇인가 | `other` 를 |
|---|---|---|
| `CATEGORIES` 배열 | **공개 랜딩 축** — sitemap · feed.xml · `generateStaticParams` · 내부 링크 | 넣지 않는다. "기타" 는 공개 주소를 가질 페이지가 아니다 |
| 필터 UI | 사용자가 고르는 목록 | **손으로 넣는다** |

`PopAllFilterBar` 주석이 그 이유를 실측과 함께 적어 뒀다 — 지역이 `other` 인 팝업이 43%
(1,046곳 중 411곳)라 그 항목이 없으면 절반 가까이가 필터로 닿지 않는다.

**그래서 `CATEGORIES` 를 건드리지 않는다.** `other` 를 배열에 넣으면 저품질 공개 페이지가
13장(단독 1 + 지역별 12) 생긴다 — 없는 문제를 푸는 대가로 SEO 표면을 늘리는 일이다.

**③ 지역 미분류가 607건(44%)** 이다. 취향 탐색은 카탈로그의 **약 절반만** 다룬다. `(서울만)`
같은 것은 구역을 아예 모르므로 어느 권역에도 못 들어간다.

### 측정에서 배운 것 — 손으로 다시 만들지 말 것

처음에는 내가 생활권 분류를 직접 만들어 쟀다. **그것은 이미 있는 `regions.ts` 를 더 엉성하게
다시 만든 것이었다**(내 것은 첫 매치, 저쪽은 "가장 정확한 한 곳"). 그 위에서 결정을 두 번
받았고(신촌 제외 → 복원) 둘 다 존재하지 않는 문제였다.

수치도 갈렸다 — 손계산은 지역 분류 68.5% · 재고 있는 조합 97%, 실제 함수는 **55.9% · 74%** 다.

**분류가 이미 코드에 있으면 그 코드를 부르는 것이 유일하게 맞는 측정이다.**

## 5. 스탬프 — 목록화만 하고 아무것도 끄지 않는다

조사가 진입점을 전수했다. **1차에서는 문서로 확정만 한다.**

- **웹 적립 1곳** — 상세의 「방문 인증」(`PopupDetailClient`). 웹에 다른 `POST /api/stamps` 경로는 없다
- **웹 여권 진입 6곳 + 딥링크 1개** — 데스크톱 헤더 · 모바일 더보기 · 홈 인사말 · 홈 벤토 · 기능소개 타일 · MY 등급카드 · `/?tab=passport`
- **앱 진입 6곳** — 단, **미병합 브랜치에만 있다**
- **백엔드 API 2개** — `POST /api/stamps`, `GET /api/stamps/my`

**구버전 앱은 끌 것이 없을 가능성이 높다.** `origin/main` 의 `popspot-app` 은 `stamp` 문자열이
**0건**이다(확인함). 스탬프를 부르는 앱 코드는 미병합 로컬 브랜치에만 있다.

**종료 결정을 1차에서 내리지 않는 이유:** 적립을 멈추면 `MateService` 의 동행 부스트 등급이
`BoostPolicy.rankOf(stampCount)` 로 **영구 고정**되고 확성기 지급 경로가 사라진다. 스탬프는
여권만의 숫자가 아니라 **등급 체계의 유일한 입력값**이다.

## 6. 착수 순서

**`CATEGORIES`·`REGIONS`·sitemap·정적 페이지를 건드리지 않는다.** SEO 표면 변경 0 이다.

- [ ] 1. Placement 시험 6개를 먼저 돌려 기준선을 잡는다
- [ ] 2. '넘기기' 저장소 + 시험 — `compareSelection.ts` 계약을 본뜬다
- [ ] 3. i18n 키 ko/en/ja 동시 추가
- [ ] 4. 탐색 UI — 홈 발견 존. `runPopAllQuery` 를 부르고 6개로 자른다.
      **선택지는 렌더 시점에 재고를 세어 0 인 것을 감춘다**(`lifestyle` 이 여기서 사라진다).
      `other` 는 `PopAllFilterBar` 처럼 손으로 넣는다
- [ ] 5. '관심 있어요' 배선 — 비회원 `toggleGuestWishlist`(`saved` 가 false 면 담겼다고 말하지 않는다) + 회원 경로
- [ ] 6. 검증 4종 + 사보타주
- [ ] 7. 스탬프 진입점 문서 확정(읽기만)

## 7. 배포와 중단

프론트 전용. 백엔드 변경 0 · 마이그레이션 0 · 데이터 변경 0. `main` 푸시 → Vercel 자동 배포.
중단은 커밋 되돌리기로 끝난다.

## 8. 이 계획이 답하지 않는 것

- **가이드 3개.** 기획에 1개로 줄이자고 돌려준다. 그 1개도 작업 3 선행.
- **지역 미분류 607건.** 취향 탐색이 카탈로그 절반만 다룬다는 사실은 남는다.
- **스탬프 종료.** 등급 체계 영향 때문에 별도 결재가 필요하다.
- **앱.** 미병합 브랜치 66커밋이 스탬프·찜 기반을 들고 있어, 병합 순서에 따라 두 번 고치게 된다.
