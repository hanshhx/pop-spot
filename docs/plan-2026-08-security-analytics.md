**왜 그렇게 했는지**를 남긴다.

이 문서를 쓰는 이유는 하나다. 판단 근거가 커밋 메시지와 대화에만 흩어져 있으면,

숫자는 그때의 실측이므로 지금 다시 재면 달라진다 — 날짜를 함께 적어 둔다.

## C — 방문 분석

### 완료

**C-1 수집 구조** (`V32__visit_event.sql`)
`visitor_id · session_id · event_type · popup_id · path · guest · created_at`.
행동 종류는 화이트리스트다 — 목록 밖의 값은 조용히 버린다. 자유 문자열로 두면
오타가 새 종류로 쌓여 집계가 갈라진다.

**C-2 보관기간·자동삭제** (`VisitService.deleteExpiredVisitLogs`)
매일 04:40 KST. `visit_log` 와 `visit_event` 를 **같은 기준**으로 지운다.
따로 두면 한쪽만 정리돼 방침의 90일 약속이 반만 지켜지는데, 그 어긋남은
아무 데도 드러나지 않는다.

**C-3 세션 · 신규/재방문** (`a1c080f`)
`GET /api/admin/visits/sessions?days=N`

- 수집은 이미 되고 있었고 **읽는 API 만 없었다.** 그래서 방문자 CSV 를 받아도
  재방문율을 계산할 수 없었다 — 유입만 늘리고 남는지는 모르는 상태였다.
- 신규를 따로 세지 않고 재방문을 센 뒤 뺀다. 두 쿼리의 기준이 달라지면 합이
  전체와 안 맞는다.
- `truncated` 를 함께 준다. 재방문 판정은 보관기간 안에서만 가능해서, 90일
  구간을 물으면 앞쪽이 전부 신규로 잡힌다. **이 값은 재방문율의 하한이다.**

**C-4 퍼널** (`e009626`)
`GET /api/admin/visits/funnel?days=N` — 방문 → 상세 열기 → 찜 → 예약·공식 링크
→ 다시 방문. 각 칸은 **사람 수**(횟수가 아니다).

- 뒤쪽 두 단계는 **수집 자체가 없었다.** `wishlist_add` · `outbound_click` 을
  새로 만들었다. 없는 것으로 퍼널을 그리면 허구가 된다.
- 첫 칸만 `visit_log` 에서 온다 — 페이지만 열고 아무것도 안 누른 사람이 분모에
  들어가야 "몇 명이 그냥 갔나" 가 보인다.
- 재방문 칸은 **세션이 달라야** 센다. 같은 세션 안의 행동을 세면 한 번 왔다 간
  사람이 전부 재방문이 된다.
- 수집 시작일은 `MIN(created_at)` 으로 데이터에 묻는다. 설정에 적으면 배포마다
  사람이 손대야 하고, 잊으면 또 틀린다.
- 뒤 칸이 앞 칸보다 커도 100% 로 자르지 않는다 — 억지로 맞추면 "이상하다" 는
  신호까지 지워진다.

## 이 플랜을 진행하며 만든 가드

정적 검사 테스트 넷. **전부 "틀린 것을 넣어 실패하는지" 까지 확인했다** — 통과하는
것만 보면 아무것도 안 보는 테스트를 통과했다고 믿게 된다. 실제로 두 번 그랬다.

| 테스트 | 막는 것 | 만든 계기 |
|---|---|---|
| `NativeQueryColumnsTest` | 네이티브 SQL 의 칼럼명 오타 | `p.id` 로 관리자 통계가 몇 주간 죽어 있었다 |
| `BeanConstructorTest` | 생성자 여럿 + `@Autowired` 없음 → 기동 실패 | 2026-08-05 실제 장애 |
| `VisitEventTypeContractTest` | 프론트/백엔드 행동 종류 불일치 | 한쪽만 고치면 화면은 정상, 통계만 0 |
| `indexableDetail.test.ts` | 색인 자격 판정의 양쪽 실패 | 느슨하면 얇은 페이지 191건, 빡빡하면 멀쩡한 게 빠진다 |

### 가드가 새어 나갔던 두 번

1. **주석 속 글자에 속음** — `src.contains("@Autowired")` 가 자바독의
   "`@Autowired` 를 지우지 마라" 에 걸려, 애너테이션을 떼도 통과했다.
   → 주석을 먼저 걷어낸다.
2. **파라미터 이름이 키워드로 읽힘** — `:from` 이 SQL 의 `FROM` 으로 파싱돼
   `e → and` 라는 엉뚱한 별칭이 만들어졌고, 그 쿼리가 검사에서 통째로 빠졌다.
   → 파라미터를 `:since`·`:until` 로, 패턴에 `(?<![:\w])` 추가.
